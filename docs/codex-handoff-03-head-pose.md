# 交接 03：歪头自动扶正 + 侧脸检测（2026-10-16，Claude）

第二轮修复（`d6d3925`）复验通过：41/41 自跑通过。用户站姿照的头顶留白从 1.5% 提到 11.4%（独立扫描输出 JPEG 测得，不是读返回值）；另两张照片和首轮边界样本都没有回退。

这一轮是新功能，起因是用户问「头倾斜的是不是没办法」。头部姿态有两种，处理方式不同：

| 类型 | 能否修正 | 本轮做法 |
|---|---|---|
| 左右歪头（roll，平面内旋转） | 能：整张图转回去 | ±15° 内自动扶正，超出就拒绝 |
| 侧脸/转头（yaw）、抬头低头（pitch） | 不能：2D 图里没有另半张脸，补出来就是造假 | 只检测 yaw，按偏移比例提醒或拒绝；pitch 本轮不做 |

## 实测数据（Claude 用 YuNet 关键点测的，测量脚本思路见文末）

| 照片 | roll | 鼻子偏离两眼中线（侧脸指标） |

## 1. `vision.detectFaces` 返回关键点

YuNet 已经输出 `kps_8/16/32`，现在被丢弃了。解码方式和 bbox 相同：第 j 个点 = `((col + kps[i*10+2j]) * stride, (row + kps[i*10+2j+1]) * stride)`，再除以 `ratio` 还原到原图坐标。
5 个点依次是：两只眼、鼻尖、两个嘴角。每个人脸对象加 `landmarks: [[x,y] × 5]`，NMS 逻辑不变。

## 2. 歪头扶正

- `roll = atan2(眼2.y - 眼1.y, 眼2.x - 眼1.x)`，换算成角度
- 常量：`ROLL_DEAD_ZONE_DEG = 1`（|roll| ≤ 1° 不旋转，避免每张图都重采样）、`MAX_ROLL_DEG = 15`
- |roll| > 15° → 失败，提示「头部倾斜约 N°，请摆正头部重拍」，不产生文件
- 1° < |roll| ≤ 15° → 把**解码后**的图像旋转 `-roll`，扩展出来的区域填**透明**（alpha=0），然后对旋转后的图**重新跑一次人脸检测**（比变换坐标简单可靠）；重新检测必须仍是 1 张脸，并且新的 |roll| ≤ 1°，否则失败
- **旋转方向要用测试钉死**，不要凭推导：把 `astronaut.png` 转 +10° 处理，输出图上重新测得的 |roll| 必须 < 1°；方向错了会变成 20°
- 自拍是镜像的，**不要做水平翻转**，和本轮无关

### 越界检查要按有效像素算

旋转会把画布扩大，四个角是填出来的透明区。现有的上溢/下溢/左右溢检查是按 `image.width/height` 算的，如果直接按扩大后的画布算，裁剪框伸进透明角也不会被判成越界，后面再被底色填上，等于把首轮修好的问题绕了回来。
要求：和图像一起旋转一张全 255 的「有效性掩码」（填 0），越界比例改成按这张掩码统计裁剪框内上沿、下沿、左右两侧的无效像素占比。阈值不变（12% / 5% / 15%）。未旋转的图，结果必须和现在完全一样。

## 3. 侧脸检测

- 指标：`yaw = (鼻尖.x - 两眼中点.x) / 两眼距离`，**在扶正之后算**（歪头会污染这个值）
- 常量（暂定，后面用更多真实照片再校）：`WARN_YAW_RATIO = 0.12`、`MAX_YAW_RATIO = 0.25`
- |yaw| ≥ 0.25 → 失败，提示「脸部没有正对镜头，请正脸重拍」
- 0.12 ≤ |yaw| < 0.25 → 成功，提示里加一句「脸部略偏向一侧，请确认是否符合正面要求」
- 按上面的数据：公有领域人像和用户站姿照不提醒；自拍 1 不提醒；自拍 2 会提醒（它本来就因为贴边被拒）
- 用户的自拍里还有一种是「眼睛看向旁边」，关键点测不出来，**不做也不要声称能测**

## 4. 成功结果

返回值里加 `roll`（扶正前的角度）、`rotated`（是否转过）、`yaw`。转过的，提示里加「已自动扶正约 N°，肩部可能略倾斜」。
